# Как сделать установку доступной по всему миру

## Короткий ответ

Да, цель продукта — чтобы оператор мог скачать установщик, запустить его на площадке и подключить совместимые камеры без ручной установки Python и настройки моделей. Но программное обеспечение обычно нельзя просто загрузить в прошивку любой CCTV-камеры: производители используют разные процессоры, операционные системы и закрытые SDK. Поэтому основной продукт устанавливается на небольшой Linux edge-шлюз рядом с NVR, а камеры подключаются к нему через RTSP/ONVIF.

## Что уже есть в проекте

- Linux Docker Compose для одного объекта.
- `deploy/install-edge.sh` — мастер первичной установки на edge-хост: домен, пароль панели и один RTSP-поток.
- Браузерная панель с TLS через Caddy, камера-переменные отделены от кода.
- Локальная обработка видеопотока; наружу по умолчанию уходят только агрегированные события.
- Поддержка нескольких камер в конфигурации пилота.

Сейчас это не публичный однокнопочный загрузчик. Нужны копия исходников, Linux, Docker и доступ к сети. Нет публикации подписанных пакетов, автоматической регистрации устройства в центральной панели или безопасного обновления целого парка.

## Путь к скачиваемой версии

### Этап 1 — повторяемый пилот

1. Зафиксировать поддерживаемую платформу: Ubuntu Server LTS x86-64, Docker Engine, список рекомендуемых GPU/CPU и лимиты потоков.
2. Выпускать версионированный edge-пакет и контейнеры с неизменяемыми версиями; не использовать `latest`.
3. Проверять подпись релиза и целостность компонентов перед установкой.
4. Улучшить мастер установки: проверка ресурсов и RTSP-доступа, настройка нескольких камер, локальный режим без публичного домена, экспорт диагностического отчёта без паролей и видеокадров.
5. Документировать обновление, резервное копирование и откат версии.

### Этап 2 — установка клиентом

Опубликовать официальный портал с выбором региона и языка, инструкциями и подписанными загрузками. Каждая площадка получает одноразовый код подключения. Edge-узел сам устанавливает исходящее TLS-соединение с control plane; открывать входящий порт на объекте не требуется. При подключении оператор подтверждает площадку, добавляет камеры с явным разрешением обработки и видит, какие потоки работают.

### Этап 3 — управление несколькими объектами

Добавить tenant/site/device-модель, роли и MFA, журнал администраторских действий, heartbeat/состояние узлов, управление конфигурациями, поэтапное обновление, health rollback, лимиты лицензии и отзыв скомпрометированного устройства. Центр должен хранить минимум: идентификаторы узла, версии, техническое состояние и разрешённые агрегаты. По умолчанию видео остаётся на объекте.

### Этап 4 — совместимость с конкретными камерами

Публиковать матрицу проверенных брендов, моделей, кодеков, разрешений и профилей RTSP/ONVIF. Отдельно разрабатывать camera-side приложения только для семейств, где доступен официальный SDK и модель прошла испытания. Не обещать «работает на любой камере» до реальной проверки.

## Критерии готовности публичного релиза

- Новый оператор ставит edge-узел по инструкции без помощи разработчика.
- Не менее 3 моделей камер и двух NVR/VMS проверены на реальных потоках и переподключении после обрыва.
- Установщик не выводит пароли и RTSP-ссылки в логи; секреты хранятся с ограниченными правами.
- Подписанное обновление проходит canary rollout и откат.
- Проверена работа без доступа к интернету после активации; поведение синхронизации описано.
- Для региона проверены применимые требования к CCTV, уведомлению людей, хранению и трансграничной передаче данных.
- Платный пилот подтвердил ценность и поддержку выбранного сценария; только после этого расширять обещания продукта.

## Реалистичный первый рынок

Начать с одного повторяемого сценария — например, анонимной занятости зон и потока людей на складах — и одного edge-профиля. Продать несколько платных пилотов с интегратором CCTV/VMS, измерить качество и стоимость обслуживания, затем открыть скачивание этого стабильного профиля. Глобальная доступность означает не только сайт загрузки: это также поддержка оборудования, безопасные обновления, локализация, региональные настройки и процесс поддержки клиентов.

Система должна применяться только к потокам, на обработку которых у оператора есть полномочия. Не добавлять распознавание лиц, установление личности или скрытый режим.
