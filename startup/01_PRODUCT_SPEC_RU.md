# Продуктовая спецификация v0.1

## Пользовательская задача

Операционный менеджер хочет понимать, когда заданные зоны на площадке заняты и как меняется поток людей за смену, не просматривая часы видео и не строя базу персональных маршрутов.

## Пользователи и роли

- **Администратор площадки:** подключает камеру, задаёт зону, проверяет состояние.
- **Оператор:** видит live-состояние и агрегированные события, подтверждает качество.
- **IT/VMS администратор:** задаёт RTSP/ONVIF, сеть, сертификаты, обновления.
- **Аудитор приватности:** проверяет параметры обработки, хранения, доступа и вывоза данных.

На MVP есть одна локальная учётная запись оператора; многопользовательские роли/SSO — отдельный этап.

## MVP-функции

1. RTSP-видеопоток и локальная камера для разработки.
2. Live-скелет и временный ID только в live-кадре.
3. Нормализованные полигональные зоны на кадре.
4. Подсчёт входов/выходов и текущей занятости зоны с коротким grace period для окклюзии.
5. Агрегация по зоне/камере/временному окну; ни один ID не записывается в базу.
6. Состояние камеры: подключена, нет кадров, переподключается, ошибка инференса.
7. Ручная настройка камер через YAML/переменные окружения; никаких секретов в интерфейсе/логах.
8. Edge-панель с авторизацией; HTTPS на удалённой площадке.
9. Автоматическое удаление событий по сроку хранения.

## Не входит в первую версию

- распознавание лиц или личности;
- межкамерная идентификация одного человека;
- рейтинг, оценка производительности или дисциплинарные решения по человеку;
- распознавание падения, СИЗ или опасного поведения без отдельной датасетной проверки;
- постоянная запись/облачная выгрузка видео;
- автоматическая загрузка прошивки на все бренды камер;
- глобальный SaaS control plane до подтверждения первого платного edge-пилота.

## Зона и события

Зона хранится в координатах кадра 0–1, чтобы переживать смену разрешения:

```yaml
zones:
  - id: dock-entrance
    polygon: [[0.10, 0.30], [0.48, 0.30], [0.48, 0.90], [0.10, 0.90]]
```

События MVP: `zone_entered`, `zone_cleared`, `zone_occupancy_changed`, `camera_offline`, `camera_online`, `inference_error`. Поля аналитики: tenant, region, site, camera, zone, время, агрегатная численность. Персональный tracker ID не сохраняется. При включении приватного режима нельзя выгружать кадры; снимки/клипы — выключены.

## Надёжность и эксплуатация

- ограниченная очередь кадров, latest-frame отображение, backoff переподключения;
- часы событий в UTC, отдельные настройки локальной временной зоны для отчётов;
- версия приложения/модели видна администратору;
- обновления подписаны и поддерживают rollback;
- камера остаётся локально доступной при потере центральной связи;
- наблюдаемость без видео: FPS, dropped/reconnect count, inference latency, free disk, GPU/CPU/RAM;
- ingest API и control plane не должны принимать произвольный RTSP URL от публичного пользователя без проверки прав/сетевых ограничений.

## Критерии приёмки пилота

- все источники явно разрешены администратором площадки;
- область зоны на UI отображается в том же масштабе, что и live video;
- счётчик сверяется с ручной разметкой по заранее выбранным временным окнам;
- события не содержат tracker ID и кадров;
- недоступная камера ясно отображается и переподключается без перезапуска всей службы;
- локальный сервис не принимает внешние подключения без HTTPS/авторизации;
- сброс/удаление площадки удаляет все события и секреты камеры.
